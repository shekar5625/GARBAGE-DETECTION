Build history

Phase by phase

01
Idea

Define the problem

ProblemSomeone has to watch for street garbage piles by hand, and reports reach the municipality late.
What we didUse existing street CCTV, detect piles automatically, and send them to a person for review.
ResultScope fixed: one class (garbage), stationary piles, human-in-the-loop review.
02
Jan 2023

Train the first model

ProblemNo public dataset of garbage piles seen from CCTV. The model had to be small enough to run without a GPU.
What we did
  • Compared YOLOv5n, YOLOv7-tiny and YOLOv8n
  • Trained YOLOv5n on Colab from COCO weights, 1000 epochs, 640 px
Resultbest1000.pt: 1.77M parameters, 3.9 MB. Still the deployed model.
03
2024 – Feb 2025

First working system

ProblemA model on its own does nothing. Detections need to be stored and reviewed somewhere.
What we did
  • main.py: RTSP frame, YOLO every 5 s
  • api.py: Flask + SQLite
  • React (CRA) dashboard: login, pending, verified, deleted, history
ResultEnd to end on the Hikvision camera. First real detections saved in Mar–Apr 2024.
04
May – Jun 2026

Rebuild the dataset and retrain

ProblemWe don't have the Colab training data that built best1000.pt, so we had nothing to retrain or measure against.
What we did
  • Roboflow "Garbage Detection" v1 (495 images, CC BY 4.0)
  • Added 99 of our own clean-road images as negatives
  • Merged 2 classes into 1; 80/20 split → 594 images, 1029 boxes
  • Trained YOLOv5s on the RTX 4050, 100 epochs
ResultYOLOv5s peaked at mAP@0.5 0.42 (epoch 12), then overfit. 4× larger, so we kept YOLOv5n for the CPU laptop.
05
Jul 2026

Make the camera feed reliable

ProblemHEVC packet loss over UDP broke frames, and a single failed read ended the program.
What we did
  • Forced RTSP over TCP
  • Reconnect instead of exit
  • Audio alert on detection
  • Setup docs, run.bat
ResultThe capture loop survives network drops without anyone restarting it.
06
Sep 2026

Run on a laptop with no GPU

ProblemRunning YOLO on every frame was too slow on CPU. Moving parked cars and trees caused false triggers. A fresh clone crashed on missing packages, and the new dashboard had never been committed.
What we did
  • Motion gating inside a hand-drawn ROI
  • m key switches models
  • Image and webcam test modes
  • New Vite dashboard (Web/) with an API proxy
  • Full requirements.txt, CPU-only DEPLOY.md
ResultInference runs only a small fraction of the time. The project installs and runs on the field laptop.
07
29 Sep 2026

Take the camera password out of the code

ProblemThe RTSP username and password were written into main.py and would have gone to GitHub.
What we didSettings now come from environment variables or a gitignored Backend/.env, with .env.example as the template.
ResultSafe to push, and each site sets its own camera.
08
3 Oct 2026

Report each pile once

ProblemThe same pile alerted and saved again on every motion trigger. main.py never posted to the API, so the dashboard stayed empty.
What we did
  • Remember piles by location (IoU or centre match), so a growing pile counts as the same pile
  • Re-check known piles; forget one after repeated misses
  • Upload new piles to /add on a background thread
ResultOne alert per pile. A cleared spot can alert again. Detections appear on the dashboard.
09
6 Oct 2026

Measure the deployed model

ProblemWe had no accuracy number for best1000.pt.
Validation · 120 images, 208 boxes
ModelSizePRmAP50
YOLOv5n (deployed)6400.570.200.23
YOLOv5n3200.590.170.24
YOLOv5s6400.660.420.41
ResultThe deployed model is usually right when it flags a pile but misses most of them. The validation set is internet photos, not our camera, so it doesn't settle which model is better for this site.
10
Next

Train on our own camera

GapTraining and test images don't look like our CCTV view.
Plan
  • Label 50–100 Hikvision frames as a test set
  • Compare YOLOv5n and YOLOv5s on them, including CPU speed
  • Fine-tune on site footage
  • Later: littering events (person detector + garbage detector)
GoalHigher recall at our camera, still real-time on CPU.
